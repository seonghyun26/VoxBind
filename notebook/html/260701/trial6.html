Trial 6 — Contrastive auxiliary (SimCLR InfoNCE + MAE)

new objectiveoff-theme from maskingnew code base = ChannelViT [7,4,2] (ρ≈0.637) · done — ρ 0.499 (−0.138, WORST)

Hypothesis

Every prior trial stayed inside reconstruction — cluster/ligand/interface masking and denoise all just change what the MAE rebuilds. But MAE never explicitly shapes the global pooled vector the frozen probe actually consumes; that vector is a by-product of per-voxel reconstruction. A contrastive objective optimises it directly: pull two augmented views of the same complex together and push different complexes apart, so the pooled representation becomes discriminative between complexes — which is exactly what affinity ranking (Spearman ρ) rewards. If the ρ≈0.637 plateau is a limit of the reconstruction objective rather than the data, a complementary contrastive signal is the one genuinely different lever left.

What was implemented

A SimCLR-style InfoNCE auxiliary, opt-in via mae.contrastive_weight (default 0 → pure MAE, bit-identical old runs). The two views are two INDEPENDENT MAE maskings of the same complex (mask-as-augmentation — no dataloader change). A 2-layer MLP projector (D→D→128) sits on the mean-pooled encoder tokens — the exact vector the probe uses — and is L2-normalized. View-a's feature is tapped for free from the MAE forward (return_tokens); view-b costs one extra trunk pass. The whole thing runs inside a single DensityViTMAE.forward so DDP's reducer sees every parameter (verified: 0 unused). The projector is pretrain-only and never part of the encoder.* strip → the frozen probe is bit-exact.

# train_density.py — NT-Xent, local in-batch negatives (bsz8 → 14/anchor)
z   = cat([z_a, z_b])                 # (2B, d), both L2-normalized projections
sim = (z @ z.t()) / temp              # temp 0.2
sim.fill_diagonal_(-inf)              # drop self
targets = [B..2B, 0..B]              # a_i ↔ b_i positive pair
L_con = cross_entropy(sim, targets)
L     = L_mae + 0.05 * L_con          # λ=0.05 balances MAE≈0.065 vs InfoNCE≈1.6

Enable: +mae.contrastive_weight=0.05 +mae.contrastive_dim=128 +mae.contrastive_temp=0.2. Smoke: 4-tuple forward, |z|=1, finite NT-Xent, projector+encoder both get finite grads, 0 DDP-unused params; full-pipeline debug logs L_con 1.66 next to L_dens 0.065.

Result & interpretation

Contrastive auxiliary badly HURT — ρ 0.499, the single worst result in the campaign (−0.138, far beyond the ±0.02 seed floor). It degraded the representation across the board: validation ρ collapsed too (best_val 0.36 vs the base's 0.53), and the frozen probe early-stopped at epoch 18–42 instead of ~100 — the features are simply worse, not just mis-calibrated.

Why instance-discrimination is anti-affinity. InfoNCE pushes every different complex apart equally, forcing the encoder to learn features that tell complexes apart as identities while becoming invariant to the within-pair augmentation. But affinity ranking needs the opposite: complexes with similar binding should sit close in representation space. Instance discrimination discards exactly the graded similarity structure ρ depends on. At λ=0.05 (contrastive ≈ MAE in magnitude) the objective had real influence — and that influence is harmful; only λ→0 (pure MAE) recovers 0.637.

Verdict. This was the last genuinely-different objective on the queue. Reconstruction (MAE) is not just the best objective — it is actively protected: both alternatives tried (denoise −0.050, contrastive −0.138) regress, and contrastive most of all. Combined with the flat data-scale result, the ρ≈0.63 plateau is firmly data / probe-ceiling bound, not objective-bound. Folded into Phase 8.
