VoxBind — conditioning on a frozen Channel-ViT (scene_vit)

📅 2026-07-01 🧩 encoder: exps/260623_ar_cvit_c1_g742 (45.7M, groups [7,4,2]) ✅ smoke-tested, original path unchanged
What changed. Added a new density_encoder_type: scene_vit to VoxBind. It loads a pretrained full-scene Channel-ViT (atomblob + density + gradmag, 13ch / groups [7,4,2]), freezes it, and uses its (B,16,64³) latent to replace the pocket+density conditioning. The noisy ligand still flows through the trainable ligand_encoder; the U-Net + fusion train on top of the frozen latent. The original VoxBind path is byte-identical when the flag is off.

1 · The conditioning path

Original (unchanged)

# pocket+density are separate branches
x = ligand_encoder(y)
  + pocket_encoder(pocket)
if with_density:
  x += density_proj(cat[x, density_encoder(density)])
x = unet(x); x = final_ligand(x)

scene_vit (new)

# one FROZEN ViT encodes the whole scene
x = ligand_encoder(y)              # trainable
scene = cat[0·lig, pocket, density+gradmag] # 13ch
x += density_proj(cat[x, frozen_vit(scene)])
x = unet(x); x = final_ligand(x)   # trained on top
The ligand channels into the frozen encoder are zeroed — the ligand is the generation target and is unavailable at sampling time, so the encoder conditions only on pocket + density. Because the pretrained encoder already carries its decoder_proj at c_out = n_channels/2 = 16, the whole module loads strict and the existing zero-init density_proj fusion is reused as-is.

2 · Three design points

PointImplementation
1. Un-hardcode channel dim The density branch width was fixed at 1–2ch. scene_vit builds DensityViT(n_in=13, channel_groups=(7,4,2), c_out=16) from n_ligand+n_pocket+n_density.
2. Zero the ligand cat([torch.zeros_like(ligand), pocket, density]) in forward (always; density=None → null conditioning for CFG). Channel-group patch embed makes the ligand group a clean constant.
3. Freeze encoder, train on top Reuses density_pretrained_path + density_freeze (models/__init__.py): strict-load → requires_grad=False → dropout off. ligand_encoder / density_proj / U-Net stay trainable.

3 · How to run

cd voxbind
CUDA_VISIBLE_DEVICES=0,1,2,3 python train.py \
  model=voxbind_scene_vit_g742 with_gradmag=true \
  # dataset must yield xray_density + xray_gradmag (with_density path)
Config configs/model/voxbind_scene_vit_g742.yaml pins the encoder dims (dim 512 / depth 12 / heads 8 / patch 8 / groups [7,4,2]) to the checkpoint — they must match or the strict load fails. Requires top-level with_gradmag=true and an X-ray (density-bearing) dataset.

4 · Verification & files

  • Smoke test passed (synthetic batch, GPU): original forward → (2,7,64³) with pocket_encoder intact; scene_vit loads the encoder strict (45.71M frozen, matches the checkpoint), forward(density) and forward(None) → (2,7,64³), and backward puts 0 grad on the frozen encoder, >0 on ligand_encoder.
  • The clean strict-load also validates the group assignment: groups 7/4/2 are distinct sizes, so ligand→g0, pocket→g1, density+gradmag→g2 must line up.
  • Files: models/voxbind.py (scene_vit branch + forward + docstring), configs/model/voxbind_scene_vit_g742.yaml (new). No change to models/__init__.py (existing loader/freeze covers it) or the dataloader (train.py/sampling_utils.py already pass density+gradmag).
  • Open question / assumption: ligand-zeroing is always-on (vs stochastic CFG dropout); intra-group channel order is the canonical voxbind order (C/O/N/S/…), shared with pretraining. Revisit if generation underperforms.
