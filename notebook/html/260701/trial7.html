VoxBind · autoresearch · dramatic change #7

Trial 7 — Learnable radius-conditioned atom embedding

representationuser ideanew code base = ChannelViT [7,4,2] (ρ≈0.637) · done — ρ 0.624 (+0.032 vs roleblob, −0.013 vs atomblob)

Hypothesis

Today atom identity is encoded two ways: atomblob gives each element its own one-hot channel; roleblob collapses everything to 2 role channels and lets the vdW blob size (diameter) carry identity. The idea here: replace "encode identity by diameter" with a learnable embedding — a small MLP φ(radius)→ℝ^k per role that maps each atom's vdW radius to a learned k-dim feature. If a continuous, learned radius→feature map is a better inductive bias than either sparse one-hot channels or raw blob-size, it should help — and a compressed k<#elements gives a "soft vocabulary" where chemically-similar atoms share representation (potentially better on the small probe).

What was implemented

A new opt-in model.radius_embed_k=k backed by RadiusAtomEmbed in models/density_vit.py. Two MLPs φ_lig, φ_poc: ℝ¹→ℝ^k are evaluated at the fixed per-element vdW radii to form embedding matrices W_lig (7×k), W_poc (4×k); the k-channel ligand/pocket grids are einsum-contractions of the one-hot occupancy with those matrices — which (for type-determined radii) equals the per-atom splat Σ_a φ(role_a, r_a)·g_a. It is a learnable front-end inside the encoder, so the frozen probe inherits it automatically; the MAE still reconstructs the RAW 13-ch atomblob+D+G, so only the input atom encoding changes.

# models/density_vit.py — RadiusAtomEmbed (k=4): raw [7|4|D,G] → [k|k|D,G]=10ch, groups (4,4,2)
W_lig = φ_lig(lig_radii)              # (7, k)  differentiable in φ
W_poc = φ_poc(poc_radii)              # (4, k)
e_lig = einsum('bcxyz,ck->bkxyz', v_lig, W_lig)   # learned k-ch ligand grid
e_poc = einsum('bcxyz,ck->bkxyz', v_poc, W_poc)
x = cat([e_lig, e_poc, density, gradmag])         # → patch_embed → encoder → recon 13ch

Enable: +model.radius_embed_k=4. Non-absorbable when k<7 (a learned soft vocabulary); recovers the element separation roleblob sums away. Smoke: default path unchanged, φ gets grads, masking commutes (zeroed voxel→zero embed), and the standalone probe encoder loads the trained encoder.* strict.

Honest caveat: ligand S and P both have vdW radius 1.8 Å, so a pure-radius embedding cannot separate them — radius-based encoding conflates same-radius elements by construction. So this is strictly ≤ atomblob in raw info; the bet is that the learned map + soft vocabulary out-generalizes the gap on the small probe.

Result & interpretation

The learned radius embedding works — and lands almost exactly where the mechanism predicts. At ρ 0.624 it beats roleblob (0.592) by +0.032 — well above the ±0.004 seed noise — confirming that a learned φ(radius) map recovers the element-identity signal that role-occupancy sums away, the whole point of the idea. It does this while compressing 11 one-hot atom channels into 8 learned ones (k=4 per role) and with the best-in-class RMSE 1.366 (≈ base 1.353).

It does not beat one-hot atomblob (0.637, −0.013). That −0.013 is real given the tight σ, and it's exactly the predicted cost: radius cannot separate ligand S and P (both 1.8 Å), so the embedding is strictly ≤ one-hot in raw information. So the learned continuous embedding is a near-lossless substitute for discrete element channels — not an improvement on them. The ρ≈0.63 plateau holds, now also against a learned atom featurization.

Follow-up — k=8 (no compression): ρ 0.613, WORSE than k=4 (−0.011). Doubling the embedding to 16 atom channels hurt (and destabilised RMSE: 1.46±0.10 vs k=4's 1.37±0.01). So the −0.013 gap to one-hot was not a compression bottleneck — k=4's compression was a beneficial regularizer on the 3,850-complex probe, and the extra capacity overfits. Same motif as the rest of the campaign (dim768, finetune): capacity hurts the frozen probe. The residual gap to atomblob is the S/P radius collision, not channel count.

Running: distance-conditioned k=8 (scales [0,2,4]) — a learned radial profile (mixture of Gaussian widths) instead of the single fixed Gaussian, so the embedding varies core-vs-shell. Tests whether a richer spatial profile (vs richer channels) helps. → trial8.html.
