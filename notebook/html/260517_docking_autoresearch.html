Method — autoresearch loop

Inspired by karpathy/autoresearch: instead of a fixed grid, an iterative loop — baseline → hypothesis → experiment → keep-or-reject → next — hill-climbs by coordinate descent (one knob at a time, 2 passes). Wall-clock docking time on this shared machine drifts heavily (the same config measured up to 1.6× apart in an earlier un-paired run), so every candidate is timed paired & interleaved: for each of 3 ligands the incumbent and the candidate are docked back-to-back and compared by the per-ligand time ratio, which cancels common-mode drift. A candidate is kept only if it is ≥5% faster on a majority of ligands and its mean Vina affinity stays within 0.6 kcal/mol of a thorough exh=16 reference dock. The converged optimum is verified — also paired — on 6 held-out ligands.

exhaustiveness — Lower exhaustiveness runs fewer Monte-Carlo searches — expect a speedup; accept it only if the affinity holds.

cpu — More CPU threads parallelise Vina's Monte-Carlo search — expect a speedup until the search saturates the available cores.

buffer — A smaller search box has fewer affinity-grid points to compute — expect a modest speedup, but a box too tight to hold the ligand slows the search down and corrupts the affinity.
