dedup vs multi-ligand are orthogonal. multi-ligand keeps different ligands from one structure (drug + cofactor + fragment). dedup collapses redundant copies of the same ligand (same CCD) in one structure — homodimer chains / symmetry copies (e.g. PDB 4g93 had ligand 0YP ×266). v2.1 uses multi-ligand + dedup(PDB,CCD) = every distinct ligand, one copy each.

v3 (ongoing) = density-aware pose dedup. Same v2.1 clean recipe, but instead of collapsing each (PDB, ligand) to ONE crop, it keeps one representative per density cluster: greedily keep a copy iff its aligned density-crop correlation with every kept copy is < τ (drop symmetry/near-identical, keep distinct poses). Sizes: ~60,871 (τ 0.85) · ~54,344 (τ 0.70) — between v2.1 (37,859, over-collapsed) and clean-no-dedup (87,926). Recovers the ~13% genuinely-distinct-density copies v2.1 threw away.

Why it matters: of 46,393 unique (PDB, ligand) pairs in v2, 26,722 (57.6%) appear more than once within the same structure (multi-chain / symmetry copies, worst 4g93/0YP ×266). Measured density-crop correlation: symmetry copies 0.86 (10/40 exactly 1.0) vs >1 Å-pose copies 0.40 (cross-ligand baseline 0.005) — so duplicates are mostly redundant, but a minority are real alternate-pose density.

2 Build lineage & the v2 audit

v1 → v2  removed filters  17.7K → 113.9K by dropping the resolution cap, dedup, single-ligand, in-vocab and train-only restrictions. Cost: 59% of crops are same-ligand-same-structure duplicates, 23% are > 2.5 Å, and pocket density was never checked.

v2 → v2.1  re-added quality  After the 260718 audit: pocket RSCC ≥ 0.8 (−111), resolution ≤ 2.5 Å (−25,939), dedup by PDB+CCD (−50,041 redundant copies) → 37,859 clean crops (~2.2× v1). Kept v2's multi-ligand + all-splits + diverse vocab (so 4 recipe axes still differ from v1).

Why v2's “6.5×” was mostly illusory:
  • 59% near-duplicates — 113,976 rows → only 46,393 unique (PDB, ligand).
  • Unique chemistry barely grew — 22,050 unique SMILES ⇒ real new chemistry ≈ 1.3×, not 6.5×.
  • +23% low-resolution (25,980 crops > 2.5 Å) and pocket density unfiltered in v1/v2.
  • Diverse-vocab noise — under [7,4,2], 1,735 v2.1 ligands (4.58%) with Br/I/metal train with that atom dropped from input but present in the density target.

Capacity gate. The official AHoJ v2c archive (40,181,598,291 bytes; 37.42 GiB) was downloaded once with size + MD5 verification. Its nested archive was not expanded wholesale: relationship metadata was streamed to compact Parquet and only candidates with local deposited coordinates plus an experimental map entered the build. The frozen corpus references the shared dataset/data/ccp4 cache, so multiple pockets from one PDB do not duplicate the map on disk.

v4 storage model

samples — one unique apo or holo pocket state. Required fields: sample_id, source, state, pdb_id, chain/model identifiers, canonical pocket ID, pocket residues/atoms, crop centre, density-file ID, experimental method/resolution, and quality flags. Holo samples carry their real ligand; apo samples set ligand_present=false and emit zero ligand atoms.

pair_edges — optional relationships, not required training records. Each edge stores sample_id_a, sample_id_b, relation/source IDs, pocket RMSD, the rigid R_a_to_b/t_a_to_b alignment, final split, and canonical pocket ID. One sample may participate in many edges.

density_files — one record per deposited experimental map. Many pocket samples may reference the same map, so full CCP4 data are never copied per pocket.

Canonical pocket rule

  • Use the VoxBind definition. A canonical holo pocket contains every protein heavy atom whose nearest holo-ligand heavy atom is within 10 Å. Transfer that identity to the mapped apo partner; never substitute AHoJ's native 4.5 Å definition.
  • Keep the model-facing VoxBind grid. Resample each structure's own experimental map to a 643 grid at 0.25 Å/voxel (16 Å cube). For paired states, first superpose the transferred pocket atoms and then sample both crystals in the same local frame; shared voxel indices are never assumed from the deposited unit cells.
  • Do not collapse by PDB. Keep spatially distinct pockets from the same structure and keep genuine alternative experimental conformations as future independently identified states.
  • Collapse the same physical pocket. Within a deposited structure/chain set, group mappings by mapped residue signature plus the canonical pocket identity; remove symmetry/logical copies while retaining spatially distinct pockets.
  • Separate samples from relationships. If several holo queries map to the same apo pocket, store the apo atoms/density once and attach several pair_edges.
  • Preserve source-state density. Apo coordinates use the apo PDB map; holo coordinates and ligand use the holo PDB map. Never transfer a holo map into an apo sample. Non-protein solvent/ions can still contribute to the experimental density; a visualization-only dry mask is never training data.

Frozen implementation

0 · Freeze inputs. Pin the v3 holo selection, PLINDER release/link hashes, AHoJ v2c archive size/checksum, PDBe retrieval date, thresholds, and downstream leakage exclusions in a v4 manifest. The protected set contains affinity val/test PDBs plus both receptor and ligand-source PDBs from CrossDocked2020 test.

1 · PLINDER apo first. Intersect linked apo structures with v3; require X-ray apo resolution ≤ 2.5 Å, pocket identity ≥ 99%, pocket lDDT ≥ 80%, complete single-chain mapping, deposited apo coordinates, and a non-empty apo CCP4 map. Retain all valid pocket-state links initially.

2 · Validate and canonicalize. Align mapped pocket residues, reject failed/low-identity fits, empty or oversized crops, weak/invalid density and nearby organic ligands, then collapse only duplicate physical apo pockets. Write independent PLINDER state samples plus optional pair edges.

3 · Reuse shared maps. Point every state to the canonical CCP4 cache and never materialize one map copy per pocket.

4 · AHoJ metadata second. Stream the official v2c archive without wholesale extraction; require exact query-ligand and apo-pocket correspondence and deduplicate against PLINDER. Alternative-holo relations remain metadata-only until target-ligand identity can be resolved without ambiguity.

5 · Gate selected AHoJ experiments. Admit only selected structures with local original mmCIF + CCP4 data, repeat the same geometry and experimental-density validation, and append independent samples plus edges.

6 · Split and freeze. Seed with PLINDER pocket_fident__50__weak__component, propagate the protected PDBs, and union exact UniProt, shared-PDB, apo–holo, interface, and official PLINDER MMS relationships. Unanchored AHoJ pockets are excluded from this frozen build. Resolve collisions as test > validation > train and require A1–A5 in acceptance.

5 Takeaways

  • Canonical best (results.html Table 1) = C+D+G, pretrained on PLINDER v1 — r 0.656 / ρ 0.637 / RMSE 1.353 on lp_edrscc_v2; best method across all four splits. The results.html headline density probe uses the smallest, curated 17.7K corpus.
  • Autoresearch high = 0.644 / r 0.660 (100M · v2 · mask0.75) numerically edges v1 but on the larger noisy corpus, and is not in the results.html table. The mask-0.75 win (+0.030 ρ) is scale-specific.
  • Data does scale (Table 4): same-recipe 9K→38K = +0.053 ρ, monotonic, non-saturating.
  • “More data doesn't help” was a recipe confound — v1-vs-v2 changed recipe + size at once. Both recipe-quality and size matter.
  • EMA decay 0.9999 is a real but narrow lever (+0.014 ρ on 40M/v2.1/100ep; hurts the 100M/50ep champion).
  • Clean ≠ enough: clean-37K (0.632) < noisy-112K champion (0.644) — size dominates; the champion's edge is raw scale.
  • Pose diversity doesn't help either: v3 (clean pose-diverse 72K, +HCS) = 0.632 — ties clean-37K despite 2× crops. New-structure scaling helps (size ladder +0.053), but extra poses of the same complexes add no probe signal. Champion 0.644 unbeaten.
