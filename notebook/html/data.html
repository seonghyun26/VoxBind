Density-pretrain dataset versions

Ligand-matched X-ray electron-density corpora for VoxBind MAE pretraining. Frozen affinity probe on lp_edrscc_v2 (Kd/Ki; 3850/817/1320); all metrics = 3 probe seeds (Pearson r / Spearman ρ / RMSE). PLINDER v2.4 is the materialized, loader-validated CASF-2016 ID30-clean derivative of v2; it has not yet been pretrained or evaluated. The v4 apo/holo pocket-state corpus — built + trained but below champion, parked — is in Appendix A.

v2.2 = v2, minus the ~5% of complexes whose ligand carries an out-of-vocab heavy atom (Br/I/B/Se/metal). It differs from v2 on one axis only — element vocab — so the 7-element ligand channels (C/O/N/S/F/Cl/P) carry every atom and no 8th “other” channel is needed. This is the clean counterpart to how the running v2 jobs already train: with n_lig_ch=7 the loader (crossdocked_density_box.py:122, atoms_channel < 7) drops the out-of-vocab atom from the input but leaves it in the density target — a 5,709-complex input/target mismatch that v2.2 removes by excluding those complexes outright. Cost is negligible: atomblob7 (v2.2, 7-ch) ρ 0.617 vs atomblob8 (full v2, 8-ch) ρ 0.624 — within ~1σ (see §3). NB: the on-disk tuple file is named …_v2p1_atomblob7.pt (a legacy label); it is not the clean-recipe v2.1 (37,859) — the two share a name prefix but are different corpora.
dedup vs multi-ligand are orthogonal. multi-ligand keeps different ligands from one structure (drug + cofactor + fragment). dedup collapses redundant copies of the same ligand (same CCD) in one structure — homodimer chains / symmetry copies (e.g. PDB 4g93 had ligand 0YP ×266). v2.1 uses multi-ligand + dedup(PDB,CCD) = every distinct ligand, one copy each.

v3 (ongoing) = density-aware pose dedup. Same v2.1 clean recipe, but instead of collapsing each (PDB, ligand) to ONE crop, it keeps one representative per density cluster: greedily keep a copy iff its aligned density-crop correlation with every kept copy is < τ (drop symmetry/near-identical, keep distinct poses). Sizes: ~60,871 (τ 0.85) · ~54,344 (τ 0.70) — between v2.1 (37,859, over-collapsed) and clean-no-dedup (87,926). Recovers the ~13% genuinely-distinct-density copies v2.1 threw away.

Why it matters: of 46,393 unique (PDB, ligand) pairs in v2, 26,722 (57.6%) appear more than once within the same structure (multi-chain / symmetry copies, worst 4g93/0YP ×266). Measured density-crop correlation: symmetry copies 0.86 (10/40 exactly 1.0) vs >1 Å-pose copies 0.40 (cross-ligand baseline 0.005) — so duplicates are mostly redundant, but a minority are real alternate-pose density.

2 Build lineage, the v2 audit & v2.4 decontamination

v1 → v2  removed filters  17.7K → 113.9K by dropping the resolution cap, dedup, single-ligand, in-vocab and train-only restrictions. Cost: 59% of crops are same-ligand-same-structure duplicates, 23% are > 2.5 Å, and pocket density was never checked.

v2 → v2.1  re-added quality  After the 260718 audit: pocket RSCC ≥ 0.8 (−111), resolution ≤ 2.5 Å (−25,939), dedup by PDB+CCD (−50,041 redundant copies) → 37,859 clean crops (~2.2× v1). Kept v2's multi-ligand + all-splits + diverse vocab (so 4 recipe axes still differ from v1).

v2 → v2.4  CASF ID30-clean  Independent branch from the actual 112,733-position v2 loader manifest: remove 11,526 positions from 6,087 PDBs with a ≥30% identity / ≥80%-shorter-coverage chain match to local CASF-2016 (214), retaining 101,207 positions from 35,590 PDBs. Atom tuples and density rows are unchanged.

Why v2's “6.5×” was mostly illusory:
  • 59% near-duplicates — 113,976 rows → only 46,393 unique (PDB, ligand).
  • Unique chemistry barely grew — 22,050 unique SMILES ⇒ real new chemistry ≈ 1.3×, not 6.5×.
  • +23% low-resolution (25,980 crops > 2.5 Å) and pocket density unfiltered in v1/v2.
  • Diverse-vocab noise — under [7,4,2], 1,735 v2.1 ligands (4.58%) with Br/I/metal train with that atom dropped from input but present in the density target.

4 Takeaways

  • Canonical best (results.html Table 1) = C+D+G, pretrained on PLINDER v1 — r 0.656 / ρ 0.637 / RMSE 1.353 on lp_edrscc_v2; best method across all four splits. The results.html headline density probe uses the smallest, curated 17.7K corpus.
  • Autoresearch high = 0.644 / r 0.660 (100M · v2 · mask0.75) numerically edges v1 but on the larger noisy corpus, and is not in the results.html table. The mask-0.75 win (+0.030 ρ) is scale-specific.
  • Data does scale (Table 4): same-recipe 9K→38K = +0.053 ρ, monotonic, non-saturating.
  • “More data doesn't help” was a recipe confound — v1-vs-v2 changed recipe + size at once. Both recipe-quality and size matter.
  • EMA decay 0.9999 is a real but narrow lever (+0.014 ρ on 40M/v2.1/100ep; hurts the 100M/50ep champion).
  • Clean ≠ enough: clean-37K (0.632) < noisy-112K champion (0.644) — size dominates; the champion's edge is raw scale.
  • Pose diversity doesn't help either: v3 (clean pose-diverse 72K, +HCS) = 0.632 — ties clean-37K despite 2× crops. New-structure scaling helps (size ladder +0.053), but extra poses of the same complexes add no probe signal. Champion 0.644 unbeaten.
  • v2.4 is the CASF-clean training choice, not a reported winner: it removes ID30 protein neighbors from v2 and is ready to train, but no v2.4 checkpoint or CASF score exists yet.

CCP4 vs CIF — density map vs coordinate model

.ccp4 — the electron-density map: a binary 3-D grid of σA-weighted 2Fo-Fc density (the experimental "image" of where electrons/atoms are, from X-ray diffraction). Source of VoxBind's density + gradmag channels. Large (~0.3–0.4 GB/entry, whole unit cell). The _diff.ccp4 variant is the mFo-DFc difference map.

.cif (mmCIF) — the atomic coordinate model: deposited atom positions, elements, residues, chains, B-factors, occupancies + metadata (resolution, space group) — the model a crystallographer fit to the density. Source of VoxBind's ligand + pocket atom channels; _updated.cif carries label_asym_id to identify the binding chains.

In short: cif = coordinates (the model), ccp4 = density (the experiment) — VoxBind voxelizes the cif atoms and reads the ccp4 density, the model and map that were solved together.

Normalization recipe (per resample dir, baked into resample.json)

Density is normalized by arcsinh soft-squash + z-score (v6): x' = (arcsinh(x/s) − μ_a)/σ_a, s = 0.5. arcsinh compresses bright atom-centre peaks; the constants are fit once over a pool of pocket-crop voxels. 2Fo-Fc: μ_a=−0.0154, σ_a=0.5085. mFo-DFc: μ_a=0.0002, σ_a=0.1606 (symmetric, ~3.7× smaller — its box is uint8-quantised over [−2, 2] vs 2Fo-Fc's [−2.2, 5]). The _diff resample dir symlinks the 2Fo-Fc train_manifest.npz: both maps share the crystal frame, so the pose (centroid / R / t) is identical.

Separate cold build-inputs from hot train-artifacts — the core inefficiency is that ccp4/ + cif/ (read once to build) sit on the same tier as the boxes/tuples (read every step):
  • Gzip the raw maps — gemmi reads .ccp4.gz transparently; CCP4 grids compress ~2–3×, so ccp4/ 228 G → ~90–110 G with zero pipeline change (only the box-build touches them).
  • Purge cold inputs after validation — once boxes + tuples are built and a run confirms them, ccp4//cif/ are only needed for rebuilds (exactly why deleting ccp4_diff/ was safe); keep a checksum manifest to re-fetch on demand.
  • One box, stacked density channels — store 2Fo-Fc + mFo-DFc as a single [N, 2, 116³] memmap instead of two files (same bytes, one read, shared pose).
  • Right-size the box — 116³ guarantees any-rotation coverage; 96³ (moderate rotations) is −44% (176 G → ~99 G/box).
  • Relative / env-rooted paths — resample.json hard-codes absolute /home/shpark/… ccp4_dir (cross-server-fragile); a VOXBIND_DATA_ROOT prefix makes the whole tree portable.
  • Reuse boxes across versions — implemented for v2.4: its position-identical v2 box is hard-linked and the filtered manifest chooses retained rows. The same row-reference design can avoid rebuilding other v2/v3 derivatives.

v4 storage model

samples — one unique apo or holo pocket state (sample_id, source, state, pdb_id, chain/model ids, canonical pocket ID, pocket residues/atoms, crop centre, density-file ID, method/resolution, quality flags). Holo carries its ligand; apo sets ligand_present=false and emits zero ligand atoms.

pair_edges — optional relationships (sample_id_a/b, relation/source IDs, pocket RMSD, rigid R_a_to_b/t_a_to_b, split, canonical pocket ID). One sample may join many edges.

density_files — one record per deposited map; many pocket samples reference the same map, so CCP4 data are never copied per pocket.

Canonical pocket rule

  • VoxBind definition. A canonical holo pocket = every protein heavy atom whose nearest holo-ligand heavy atom is within 10 Å; transfer that identity to the mapped apo partner (never AHoJ's 4.5 Å).
  • Model-facing grid. Resample each structure's own map to 643 @ 0.25 Å/voxel (16 Å cube); for pairs, superpose the transferred pocket atoms then sample both crystals in one frame.
  • Do not collapse by PDB; keep spatially distinct pockets and genuine alternative conformations. Collapse the same physical pocket (mapped-residue signature + canonical identity) to drop symmetry copies.
  • Separate samples from relationships; store shared apo atoms/density once, attach several pair_edges.
  • Preserve source-state density. Apo coords use the apo map; holo coords + ligand use the holo map. Never transfer a holo map into an apo sample.
