Feature Provenance

The important caveat: before the patch in this audit, feature caches were named only as {condition}_e{epoch}_{version}.pt. The three atomblob_density_gradmag checkpoints therefore overwrote atomblob_density_gradmag_e99_v5.pt.
  • The current atomblob_density_gradmag_e99_v5.pt bundle points to the 260608 w1 checkpoint.
  • The final CSVs can still be valid if each probe was run immediately after the matching feature extraction. Logs confirm this for 260605, 260606 invfreq, and 260608 w1.
  • The 260605 and 260608 probes used --allow_stale_features because strict validation expected the default 260606 mapping, not their custom checkpoint. That was an artifact of the probe code, not necessarily bad data.
  • The density-only feature bundle points to the correct 260606 density checkpoint and has clean v5 metadata; however, I did not find a matching filtered density-only probe log, only the CSV.

Code Fix Applied

  • features --tag TAG now writes tagged feature caches such as atomblob_density_gradmag_e99_v5_260608_w1.pt.
  • probe --feature_tag TAG loads the matching tagged feature cache. This is separate from result --tag, so old untagged features remain usable.
  • probe --exp_dir EXP now makes strict cache validation expect the custom checkpoint for one-condition probes, removing the need for --allow_stale_features in intended custom-exp comparisons.
  • features --exp_dir without --tag now warns that it will write to the shared condition cache path.

Recommended Rerun Pattern

Use this pattern for every same-condition checkpoint comparison:

python dataset/01c_pdbbind_probe.py features \
  --condition atomblob_density_gradmag \
  --voxel_version v5 \
  --epoch 99 \
  --exp_dir exps/<checkpoint_exp> \
  --tag <run_tag>

python dataset/01c_pdbbind_probe.py probe \
  --conditions atomblob_density_gradmag \
  --voxel_version v5 \
  --epoch 99 \
  --cl1_only \
  --tag <run_tag> \
  --feature_tag <run_tag> \
  --exp_dir exps/<checkpoint_exp>;
