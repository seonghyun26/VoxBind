Splat-and-Mask: exploiting a frozen MAE for de novo ligand generation

A representation + sampling swap so the pretrained atomblob density-MAE stays in-distribution the whole way through generation — atoms as a set of 3D Gaussians, differentiably splatted into the voxel field the encoder was trained on, filled in by iterative masking instead of Gaussian denoising.
The one idea. VoxBind's walk-jump corrupts the ligand with Gaussian noise; our frozen MAE was pretrained with masking on clean voxels. That mismatch is what makes "let the frozen encoder see the ligand" fail. Fix it at the root: represent the ligand as an explicit set of atom-Gaussians, splat them into the voxel density the MAE expects, and generate by iterative unmasking (MaskGIT/MAE-style). The encoder then only ever sees partially-masked clean complexes — exactly its pretraining diet.

1 Why a new sampler at all

The frozen encoder (atomblob7 v2.1 ChannelViT, 45.7M, pretrained as a Masked Autoencoder on 110k PLINDER complexes, mask_ratio 0.5) has only ever seen two things: clean atom-blob voxels, and whole patches masked out. Walk-jump feeds it neither — it adds continuous Gaussian noise to the ligand, and at sampling step 0 the ligand is pure noise. A frozen network can't adapt to a corruption it never saw.

Fig 1. The corruption a model trains under has to match the corruption the frozen encoder sees at inference. Walk-jump's Gaussian noise doesn't; MAE-style masking does — so we change the sampler, not the encoder.

2 Represent the ligand as atom-Gaussians

A molecule is a sparse set of 3D Gaussians — one per atom (position + a width set by its element + a "colour" = element channel). This is exactly the primitive Gaussian splatting uses for scenes. And VoxBind's atom-blob voxelizer is already the splat: it rasterizes those atom-Gaussians onto the 64³ grid. Today VoxBind generates the rasterized grid; we instead generate the explicit Gaussian set and splat it — sparse, continuous, and naturally maskable.

Fig 2. Two views of the same ligand. We generate the sparse Gaussian set (left) and render it into the dense voxel field (right) that the frozen encoder understands. The splat is differentiable, so gradients flow back to atom positions — the Gaussian-splatting move.

3 Generation = iterative masked inpainting

Instead of denoising, we inpaint the ligand into the pocket — literally what an MAE learned to do. The pocket + density stay clean and fully visible; the ligand starts fully masked and is filled in over a handful of steps, committing the most confident atoms each round (a cosine mask schedule). The frozen encoder is in-distribution at every step.

Fig 3. The loop. The trainable set-decode head predicts the masked atoms from the frozen encoder's read of the splatted, partially-filled complex; confident atoms are committed and the rest re-masked. Because the ligand is only ever masked (never noised), and the pocket/density are always clean, the frozen encoder never leaves its pretraining distribution.
Fig 4. Generation as progressive inpainting inside a fixed pocket: atoms are committed a few at a time over T steps (a cosine mask schedule), analogous to MaskGIT parallel decoding. Adding/pruning atoms across steps handles variable molecule size — the splatting analogue of adaptive densification.

4 Why this is the right fit

  • In-distribution by construction. The frozen encoder only ever sees masked clean complexes — the corruption it was pretrained on. The Gaussian-noise OOD problem simply cannot arise.
  • Fullest use of the MAE. A masked autoencoder repurposed as a masked generator — the network is used almost exactly as it was built, encoder + a light decode head.
  • Sparse & continuous. ~40 atom-Gaussians instead of a 64³×7 grid; atom positions aren't quantized to a lattice, so geometry is cleaner and memory drops sharply.
  • Masking is natural on a set. You mask atoms, not arbitrary grid patches — a well-defined, permutation-friendly corruption.
  • Adaptive densification ↔ variable atom count. Splatting grows/prunes Gaussians; here that becomes add/remove-atoms, a clean handle on "how many atoms?" — a perennial SBDD headache.

6 Design sketch & open questions

  • Atom-set parameterization. Each atom = (xyz ∈ ℝ³, element ∈ {C,N,O,…}, width). Positions continuous; element as a small categorical; a shared isotropic width per element (or learned).
  • Differentiable splat. Reuse VoxBind's voxelizer but keep it autograd-friendly (sum of element-wise Gaussians onto the 13ch grid) so position gradients flow from the encoder loss.
  • Set-decode head. A light transformer/GNN head over slot tokens that reads the frozen encoder's features and predicts the masked atoms' (xyz, type) + a confidence for the commit schedule.
  • Stochasticity (the crux). The current MAE is a regression AE (mean reconstruction → low diversity). To sample diverse ligands, add either a VQ codebook over atom-slots (categorical MaskGIT) or a small per-atom generative head (mixture / mini-diffusion).
  • Bonds. Atoms alone give no connectivity — keep VoxBind's voxel→bond inference on the final splat, or add a pairwise bond head.
  • Variable size & permutation. Slot-based set generation with an explicit "add/stop" action; train with Hungarian-matched or masking-consistent loss so order doesn't matter.
  • De-risk first (cheap, no training): the noise-robustness probe on the frozen encoder — confirm the latent tolerates masking far better than Gaussian noise, validating the whole premise before any rebuild.
